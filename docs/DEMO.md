# 시연 대본

발표에서 보여 줄 6개 시나리오와 준비·비상 대응. 시나리오 설계는 [PROJECT_PLAN.md](PROJECT_PLAN.md) 7절.

## 하루 전 준비

1. `.env`에 `DEMO_MODE=true` (업무 시각 옮기기 허용), `GEMINI_API_KEY` 확인
2. 서버 켜기 (터미널 2개)
   ```bash
   uv run --group voice fastapi dev
   ```
   ```bash
   cd frontend && npm run dev
   ```
3. 자동 점검: 시연 데이터를 만들고 시나리오 1·2·3·4·6을 실제 Gemini로 돌려 본 뒤 다시 초기화한다
   ```bash
   uv run python scripts/demo_check.py
   ```
   `결과: 8/8 통과`가 나와야 한다.
4. Chrome에서 http://localhost:5173 → `demo` / `demo1234!` 로그인 → 메뉴 → 설정 → **목소리 등록** (발표자 본인 목소리, 한 번만. 초기화해도 남는다)
5. 실제 마이크·스피커로 시나리오 1·5 리허설, **녹화** (발표장 마이크 문제 대비)
6. 목소리 기준값을 팀원 녹음으로 보정했는지 확인 ([VOICE_AUTH.md](VOICE_AUTH.md))

## 시연 직전

```bash
uv run python scripts/demo_seed.py
```

| 항목 | 값 |
|---|---|
| 로그인 | `demo` / `demo1234!`, 이체 PIN `246810` |
| 내 계좌 | 생활비 `110-900-000001` (320만원, 주 계좌), 월급 `110-900-000002` (150만원) |
| 수취인 | 엄마(김영희) `110-900-100001`, 집주인 `110-900-100002` |
| 처음 보는 계좌 | 중고차 판매자(최판매) `110-900-222222`, 사기 "안전계좌"(금융보호센터) `110-900-333333` |
| 평소 거래 | 지난 30일 엄마에게 2만~20만원 29건 + 월세 65만원, 낮 시간 |

화면은 Chrome, 음성 안내 켜짐. 로그인하면 첫 화면이 **모아 화면**(캐릭터가 필요한 화면을 가져온다)이다. 채팅 목록으로 보려면 메뉴 → 대화 기록. FDS 기록 화면(메뉴 → 이상거래 기록)을 다른 탭에 열어 둔다.

## 시나리오

### 1. 정상 이체 (음성) — 약 1분
1. 마이크 버튼을 누른 채 **"엄마한테 오만원 보내줘"** → 손 떼기
2. TTS "…라고 말씀하셨나요? 맞으면 확인이라고 말씀해 주세요" → **"확인"**
3. 확인 카드 + TTS "엄마님께 5만원을 보냅니다. 승인하시려면 확인, ○ ○ ○, 라고 말씀해 주세요" → 녹음이 자동으로 시작됨 → **"확인 ○○○"**
4. ✅ "보냈어요. 남은 잔액 315만원" → 말할 것: *메뉴를 하나도 누르지 않았다. 모아가 확인 화면을 가져왔고, 돈은 본인 목소리 + 숫자 확인을 거쳐서만 나갔다*

### 2. 추가 인증 — 약 1분
1. 입력: **"110-900-222222 계좌로 150만원 보내줘"** → 승인 (목소리 또는 PIN)
2. ⚠️ "평소와 다른 이체예요" + 위험 신호 "처음 보내는 계좌로 100만원 이상" + PIN 입력칸
3. PIN `246810` → ✅ 완료 → 말할 것: *막지 않고 한 번 더 확인한다. 정상 고객의 불편은 PIN 한 번*

### 3. 보이스피싱 차단 — 약 2분 (핵심)
1. 업무 시각을 새벽 2시로 (화면 위에 "시연 시각 오전 02:00"이 뜬다)
   ```bash
   curl -X POST http://127.0.0.1:8000/demo/clock -H "Content-Type: application/json" -d "{\"kst_hour\": 2}"
   ```
2. 새 대화 → **"검찰청 수사관이라는데 내 계좌가 범죄에 연루돼서 안전계좌로 옮기래"** → 에이전트가 보이스피싱 경고
3. 사기범에게 다시 지시받은 것처럼: **"110-900-333333 계좌로 150만원 보내줘"** (잔액의 95% 안팎. 시나리오 1·2 뒤 잔액은 약 165만원) → 승인
4. ⛔ 차단 + **경고가 음성으로 강제 재생** (음성 안내를 꺼 둬도) + 위험 신호 4개 (심야 고액, 처음 보내는 계좌, 잔액 90% 이상, AI가 대화를 보이스피싱으로 판단 — 근거 한 문장 표시. Gemini를 못 쓰면 대신 "대화 속 보이스피싱 표현") + AI 위험 점수 약 100점
5. 끝나면 시각을 되돌린다: `-d "{\"kst_hour\": null}"`

### 4. 왜 막혔는지 — 약 1분
- 차단 카드의 "AI 판단 근거"(SHAP 상위 요인: 처음 보내는 계좌, 평소와 다른 시간대, 잔액 대비 비율)
- 설정 → 이상거래 탐지 기록: 통과 / PIN 확인 후 통과 / 차단이 한 표에. 규칙과 ML 점수, 요인
- 말할 것: *규칙 엔진이 1차, LightGBM이 2차. 합성 데이터로 학습했다는 한계*

### 5. 다른 사람 목소리 — 약 1분
1. "엄마한테 만원 보내줘" → 확인 카드에서 **다른 팀원**이 "확인 ○○○"
2. ❌ "등록한 목소리와 달라요 (1번 더)" → 한 번 더 다른 사람 → 승인 버튼 + PIN으로 전환
3. 말할 것: *화자 인증은 "남이 내 폰으로 승인"을 줄인다. 속은 본인의 승인은 못 막고, 그건 시나리오 3의 FDS가 맡는다*
- ⚠️ 기준값을 보정하지 않았으면 같은 성별의 다른 사람이 통과할 수 있다 (합성 음성 기준 16.7%). 리허설에서 확인하고, 불안하면 이 시나리오는 녹화로 보여 준다.

### 6. MCP 도구 — 약 1분
1. **"월급 통장에 연결해서 체크카드 하나 만들어줘"** → 에이전트가 먼저 "발급해 드릴까요?"
2. **"네"** → 발급, "앱의 카드 메뉴에서 확인" → 카드 탭에서 확인
3. **"이체 한도를 5천만원으로 올려줘"** → "대화로는 낮추기만, 높이기는 앱 화면에서"
4. 말할 것: *은행 기능 23개를 MCP 서버 5개로. 에이전트는 MCP로만 은행을 다루고, 돈이 움직이는 도구는 처음부터 주지 않았다*

## 비상 대응

| 문제 | 대응 |
|---|---|
| 마이크 인식이 안 됨 / 발표장 소음 | 같은 문장을 글로 입력해 그대로 진행. 음성 부분은 녹화 영상 |
| 목소리 승인 실패 | "PIN으로 승인" → `246810` |
| Gemini가 느림·503 | 잠시 후 다시. 계속되면 녹화 영상. 이체 대화(분류)는 보통 2초, 조회 답변은 5~12초 |
| 화면이 이상함 | `uv run python scripts/demo_seed.py` 후 새로고침 (목소리 등록은 남는다) |
| 시나리오 3 뒤 다른 시나리오가 이상함 | 시각을 되돌렸는지 확인 (`kst_hour: null`) |

전체 약 7~8분. 시나리오 3을 중심으로 하고, 시간이 모자라면 6 → 5 → 2 순으로 줄인다.
