# 음성 승인 (화자 인증)

이체 확인 카드를 버튼 대신 목소리로 승인한다. 설계는 [PROJECT_PLAN.md](PROJECT_PLAN.md) 3.5절, 코드는 `src/avengers_bank/domains/speech/`.

## 흐름

```
설정 > 목소리 등록: 동의 + 문장 3개 녹음 + 비밀번호 → POST /voice/profile → 화자 임베딩(192차원) 평균을 Fernet 암호화해 저장
확인 카드: 서로 다른 숫자 3개(2~9) 챌린지 → TTS "…승인하시려면 확인, 팔 구 오, 라고 말씀해 주세요"
브라우저: MediaRecorder 녹음 → 16kHz 모노 WAV 변환 → POST /voice/approvals
서버: ① Gemini 오디오 입력으로 숫자 인식 = 챌린지  ② ECAPA 임베딩 코사인 유사도 ≥ 기준값  → 음성 승인 토큰(2분, 카드에 묶임)
이체: POST /transfers + voice_approval_token → 이후 FDS 판정은 버튼 승인과 같다
실패: 카드당 2번. 다 쓰면 VOICE_LOCKED → 승인 버튼 + PIN
```

목소리를 등록한 사용자가 버튼으로 승인하면 FDS 등급과 상관없이 PIN이 필요하다 (`PIN_REQUIRED`). 버튼만으로 통과시키면 남이 폰을 들고 버튼을 누르는 것을 막을 수 없다. 목소리 등록·재등록·삭제에는 비밀번호를 다시 받는다 (남이 자기 목소리로 바꿔치기하는 것을 막기 위해).

## 구성

| 부분 | 사용 | 비고 |
|---|---|---|
| 화자 임베딩 | SpeechBrain `spkrec-ecapa-voxceleb` (PyTorch CPU) | `uv sync --group voice`. 모델 약 85MB를 처음 쓸 때 `.models/`에 받는다. 임베딩 1회 약 0.1초 |
| 숫자 인식 | Gemini 오디오 입력 (`GEMINI_FAST_MODEL`) | 클라이언트 STT 결과는 믿지 않는다. 약 3초. 15초가 넘으면 503 → 버튼 + PIN |
| 암호화 | `cryptography` Fernet, `.env`의 `VOICE_ENCRYPTION_KEY` | 키를 바꾸면 기존 등록 목소리를 읽을 수 없다 (다시 등록) |
| 녹음 형식 | 브라우저에서 16kHz·모노·16bit WAV로 변환 | 서버에 ffmpeg 불필요 |

PyTorch가 없거나 암호화 키가 없으면 `GET /voice/profile`의 `available`이 false이고, 확인 카드에 숫자 챌린지가 붙지 않으며 승인은 버튼(+ 등록자는 PIN)으로 된다.

## 확인한 것 (2026-11-04)

Gemini TTS로 만든 합성 목소리 4종(Kore·Aoede 여성, Puck·Charon 남성)으로 확인했다. **실제 사람 목소리로는 아직 확인하지 않았다.**

| 항목 | 결과 |
|---|---|
| 숫자 인식 | "확인 사칠이" 4종 모두 472로 정확히 인식. 같은 숫자 반복("이 이 이")은 틀려서 서로 다른 숫자, 0·1 제외로 바꿈 |
| 실제 서버 끝까지 | 본인 + 맞는 숫자 → 승인·이체 완료 / 틀린 숫자 → `VOICE_DIGITS_MISMATCH` / 2번 실패 → `VOICE_LOCKED` |
| 브라우저 끝까지 | Chrome 녹음(webm/opus) → WAV 변환 → 승인 → 이체 완료 (마이크 입력을 합성 음성으로 바꿔서 확인) |
| 화자 분리 (등록 3문장, 시도 3문장씩) | 아래 표 |

`scripts/voice_calibration.py` 결과 (합성 목소리 4명):

| 기준값 | 본인 거부율 | 타인 통과율 |
|---|---|---|
| 0.40 | 0% | 33.3% |
| **0.45 (현재 기본값)** | **0%** | **16.7%** |
| 0.50 | 33.3% | 8.3% |
| 0.60 | 75.0% | 2.8% |
| 0.65 | 91.7% | 0% |

- 남성 목소리와 여성 목소리는 잘 갈린다 (본인 0.50~0.52, 다른 성별 0.19).
- 같은 성별의 합성 목소리끼리는 겹친다 (Kore↔Aoede 최대 0.61). 합성 목소리는 한 모델에서 나와 실제 사람보다 비슷할 가능성이 크지만, 확인 전까지는 **"같은 성별의 다른 사람이 통과할 수 있다"**고 보는 것이 맞다.
- 승인 문장을 6~7초로 늘려도 분리가 좋아지지 않았다.

## 남은 일

1. **기준값 보정 (필수):** 팀원 3명 이상이 각자 6개 이상 녹음(`이름_번호.wav`) → `uv run --group voice python scripts/voice_calibration.py 폴더` → 타인 통과율이 0에 가까운 가장 낮은 값을 `.env`의 `VOICE_SIMILARITY_THRESHOLD`에. 결과를 이 문서에 추가한다.
2. 실제 마이크로 Chrome에서 등록·승인 확인 (조용한 곳 / 시끄러운 곳).
3. 발표에서 한계를 밝힌다: 화자 인증은 "남이 내 폰으로 승인"을 줄이는 장치이고, 보이스피싱에 속은 본인의 승인과 실시간 음성 복제는 막지 못한다. 그 경우는 FDS가 맡는다.

## 개인정보

목소리 특징은 개인정보보호법상 민감정보(생체정보)다. 별도 동의를 받고(`consent`), 원본 녹음은 저장하지 않으며(등록·승인 모두 판정 직후 버림), 임베딩은 암호화해 저장하고, 사용자가 언제든 지울 수 있다.
